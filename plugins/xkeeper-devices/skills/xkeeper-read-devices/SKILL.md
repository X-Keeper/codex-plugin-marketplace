# Чтение устройств X-Keeper

## Порядок работы

1. Использовать только инструменты MCP X-Keeper для получения данных X-Keeper. Не использовать Pinokio, браузер, терминал, shell, прямые HTTP-запросы или другие MCP, если нужный инструмент X-Keeper доступен.
2. Найти API-ключ в текущей задаче. Если пользователь назначил ключу имя, сопоставлять это имя со значением только в пределах текущей задачи.
3. Если ключ не передан, запросить его до вызова инструмента. В аргумент `apiKey` передавать точное значение ключа, а не его имя.
4. Выбрать самый узкий подходящий инструмент чтения и передать только необходимые параметры.
5. Вернуть результат по-русски, не повторяя API-ключ и не раскрывая лишние чувствительные поля.

## Выбор инструмента

- `status_get` — актуальный статус устройств по SIM.
- `devices_get` — сведения и текущие параметры устройств по SIM.
- `settings_get` — настройки конкретного устройства по его идентификатору и при необходимости паролю.
- `raw_history_get` — сырая история событий конкретного устройства из xkdb; ключи ответа — короткие имена xkdb без переименования. Требует постоянный секрет `rawHistorySecret` (один общий для аналитиков, выдаёт администратор) помимо `apiKey`. Всегда передавать границы времени в `filter.device_dt` (`>=` и `<=` в формате YYYY-MM-DD HH:mm:ss): без них запрос охватывает историю с 2015-01-01 и выполняется очень долго. Опциональные actions: `decode_address` — адрес по координатам, `check_inside_geozone_id` — проверка вхождения в геозону.
- `xkdb_fields_reference` — справочник расшифровок полей ответа `raw_history_get`: короткое имя, длинное имя, описание, тип, значения. Вызывать при интерпретации истории, когда встретилось незнакомое поле; без аргументов возвращает общий перечень, с `fields` — детальные карточки.
- `geozones_get` — доступные геозоны.
- `geozones_report_entry_one` — нахождение устройств в геозонах.
- `groups_get` — группы устройств.
- `lists_get` — списки устройств.
- `panel_get_objects` — объекты панели через одноимённый читающий метод devices-api.
- `silent_report_get` — устройства, давно не выходившие на связь.
- `motionless_report_get` — неподвижные устройства.
- `devices_get_inverted_in_motion` — перевёрнутые устройства в движении.
- `devices_filter_by_total_move_time` — устройства с заданным временем движения.

Частые поля истории для быстрой ориентации: `device_dt`/`create_dt` — время события и записи (UTC), `location` — координаты маяка (приоритет GPS > WIFI > GSM), `location_type` — источник координат (0 GPS, 1 GSM, 2 WIFI), `ig` — зажигание (0/1), `acc_motion` — движение (0 спокойствие, 1 движение, 2 начало, 3 тряска), `speed` — км/ч, `odometer` — метры, `geozones` — id геозон на момент выхода на связь, `ebs` — статусы блокировки двигателя (массив из 5 элементов), `pip`/`piv` — процент и вольты батареи, `pev` — вольты внешнего питания, `te` — температура. Полные расшифровки — через `xkdb_fields_reference`.

`panel_get_objects` и параметры аккаунта панели относятся к опубликованному контракту devices-api. Не обращаться к panel-backend напрямую. Запрашивать логин, пароль панели или пароль устройства только тогда, когда они обязательны для выбранного инструмента и не были переданы пользователем.

## Работа с ключом

- Не выводить ключ в ответе, даже если он уже появился в сообщении пользователя.
- Не сохранять ключ в файл, память MCP или другой инструмент.
- Не обещать доступность ключа в новой задаче.
- Передавать ключ в каждом вызове MCP.
- При ответе `401` или `403` сообщить, что devices-api отклонил ключ или не разрешил доступ. Не пытаться обходить отказ и не заменять ключ учётными данными панели.
- Если передано несколько именованных ключей и выбор неоднозначен, уточнить имя нужного ключа.

## Ограничения

- Не вызывать изменяющие или удаляющие методы.
- Не придумывать отсутствующие инструменты и не превращать задачу в произвольный HTTP-запрос.
- Если пользователь просит изменить данные, объяснить, что плагин поддерживает только чтение.
- Не запрашивать больше полей и устройств, чем требуется для ответа.
